## Findings

### Architecture delta

**Layering respected.** Presentation (`app/`, `components/`) calls application services (`lib/services/`), domain rules live in `lib/domain/` without I/O, and data access is isolated in `lib/db/`. No cycles detected in import graph of changed files.

- **Source:** `grep` on `@/lib/` imports across `champions-app/`; `epic-1-context.md` lines 25–26.

**Middleware split is sound.** `middleware.ts` delegates to `runAuthMiddleware` (`lib/auth/middleware-handler.ts`) and policy rules in `lib/auth/middleware-policy.ts`. Auth.js boundary stays in root `auth.ts`.

- **Source:** `champions-app/middleware.ts:1-17`, `lib/auth/middleware-handler.ts:5-19`.

**Intentional matcher duplication.** `AUTH_MIDDLEWARE_MATCHER` in `middleware-policy.ts` mirrors `middleware.ts` `config.matcher` because Next.js requires literal paths. Comment documents the coupling.

- **Source:** `lib/auth/middleware-policy.ts:10-11`, `middleware.ts:9-17`.
- **Disposition:** accept as-is (framework constraint).

### Duplication map

**Duplicated Next.js component mocks in dashboard tests.** `next/image` and `next/link` mocks appear separately in `app-bar.test.tsx`, `nav-tabs.test.tsx`, `layout.test.tsx`, `dashboard-shell.test.tsx`.

- **Source:** `deferred-work.md` lines 50–51; file paths under `components/dashboard/` and `app/(dashboard)/`.
- **Disposition:** defer — refactor when shared test utilities land.

**Per-service test pattern is consistent** (domain error constants + vi.mock db). No divergent implementations of the same business rule across stories.

### God-class / size growth

No file in `lib/services/` exceeds 70 lines of implementation code. Highest churn files in the epic range are spec artifacts and `globals.css` (217 lines current — design tokens + Menthe Douce theme, expected for story 1.5).

- **Source:** `git_evidence.py` `files` ranking; `wc -l` on `lib/services/*.ts` (08-26-2026).

### Pattern divergence

**Consistent domain-first validation.** Registration, authentication, and class creation each validate in `lib/domain/` before service I/O (`registration.ts`, `authentication.ts`, `class.ts`).

- **Source:** `lib/services/register-teacher.ts:7-8`, `authenticate-teacher.ts:4`, `create-class.ts:6`.

**NFR9 timing fix applied in login.** Unknown-email logins run `bcrypt.compare` against a dummy hash.

- **Source:** `lib/services/authenticate-teacher.ts:13-15`, `39-41`; `deferred-work.md` line 33 notes fix.

**Minor divergence:** `button.tsx` uses unquoted import style (`@/lib/utils`) vs quoted elsewhere — cosmetic only.
