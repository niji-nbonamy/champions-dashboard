- (decision) Multi-user: up to 2 teachers using the app concurrently, each for their own class — not a single shared class
- (decision) Cloud persistence required: laptop + mobile per teacher implies server-side data store and sync — no local-only
- (decision) Offline not required — online-only acceptable
- (direction) User prefers Next.js (known); open to alternatives but Next is the lean default
- (constraint) Hosting must be free — constrains provider and tier choices
- (event) Coaching path selected; deliverable: spine only
- (decision) Same school, 2 teachers: each teacher sees and manages only their own class — strict class-level data isolation
- (decision) Auth: email + password; teachers self-register (no admin provisioning)
- (constraint) GDPR: student roster is personal data — database hosted in EU region
- (decision) No real-time sync: page load / refresh is sufficient for laptop+mobile concurrent use
- (decision) Stack: Next.js 16 on Vercel Hobby + Neon Postgres (EU Frankfurt) + Auth.js v5 with Neon adapter — email/password credentials, keeps auth in Next ecosystem
- (decision) Paradigm: layered monolith — UI/routes → application services → domain logic (pure) → Drizzle/Postgres
- (assumption) One class per teacher per school year — no multi-class teacher in MVP
- (assumption) Vercel Hobby non-commercial clause acceptable for pilot scale (2 teachers); revisit if school adopts formally
- (event) spine finalized
- (decision) Grade-level agnostic (AD-11): no school grade (CE2, CM1, etc.) in schema, UI, or rules — tool serves 2 different grade levels; CHAMPIONS color levels unchanged
